# 捡漏算法与运行语义

本文说明普通道具和紫卡捡漏的价格基准、候选门槛及恢复行为。Bot 入口包括 `捡漏添加`、
`捡漏列表`、`捡漏删除` 和 `捡漏紫卡`；全局参数以管理控制台“系统设置”中的显示值为准。

## 普通道具

普通道具以 warframe.market `statistics_closed.90days` 中最新日桶的 `avg_price` 为基准。
系统只对全市场 WebSocket 实时收到的新建订单判断一次，不读取实时订单簿计算地板价，也不通过
HTTP 回放断线期间的订单。旧订单改价和断线期间漏掉的订单不会补推。

启动时如果目录或统计数据尚未就绪，实时事件最多在内存中暂存五分钟；数据就绪后仍只判断一次。
有等级道具仅支持 0 级和满级，等级与规格必须和统计桶精确匹配；`maxRank=0` 的道具不显示也不
接受等级选项。

虚空商人携带的道具会暂停捡漏，直到 WFM 出现商人激活后的新日桶。系统启动时立即查询商人状态，
之后按事件边界调度并定期校准；请求失败时使用最长一小时的指数退避。

## 紫卡

系统按武器每小时采集一次价格样本，新建监控配置会立即触发一次采集。样本只使用 `online` 和
`ingame` 卖家的明确直售一口价，两种状态平等排序，不按卖家去重。

价格从低到高排序后排除最低价，以第 2～5 名的算术平均作为小时样本。出现以下任一情况时舍弃
本小时：

- 明确直售订单少于五个；
- 第 2～5 名价格的离散度超过 35%。

最近若干小时的有效小时样本再做不加权算术平均，形成滚动均价。默认窗口为 24 小时，最低为
12 小时；最低有效样本数默认是 1，且不能超过窗口时长。

候选卖家可以是 `offline`、`online` 或 `ingame`，但订单必须满足：

- 是明确直售而非竞拍起拍价；
- WFM `created` 距检查时刻不超过一小时；
- 低于监控条目或全局设置的折扣门槛。

候选判断只读取已缓存的滚动均价，不在判断时临时查询订单簿。已提醒的拍卖 ID 永久保存，重启后
不会再次提醒。

紫卡捡漏没有专属总开关或单项开关；监控条目添加后不再检查额外启停状态。采样与投递仍受目标
启用状态、Discord 私聊总配置等通用条件约束，目标停用时不会推送。

## 黑名单与参数

WM 和游戏频道卖家黑名单按目标、按来源分别保存，只过滤对应来源的紫卡狙击，不过滤普通道具或
紫卡捡漏。添加、删除和查看命令省略范围时，已开启频道消息的目标同时操作 WM 与频道黑名单，
未开启时只操作 WM；显式指定 `WM` 或 `Channel` 时只操作该来源，显式频道范围在目标关闭频道
消息时静默停用。

控制台“系统设置”维护四项全局算法参数：

- 普通道具默认折扣；
- 紫卡默认折扣；
- 紫卡滚动均价时长；
- 紫卡最低有效样本数。

单个监控条目可以覆盖默认折扣。计算过程保留小数，只在通知展示时取整。
