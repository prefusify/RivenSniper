RivenSniper 一键启动说明（Windows 11）
=================================

请保留整个项目文件夹，不要只把启动脚本移动到桌面。
所有窗口都会给出中文提示；失败时请保留或截图完整错误信息。


一、只使用 QQ Bot
----------------

1. 双击「启动BOT.cmd」。
2. 首次运行会准备 Python 和依赖，所需时间取决于网络速度。
3. 按提示填写接收推送的 QQ 群号和该群唯一所有者的 QQ 号。
4. 启动器会显示 SnowLuma OneBot v11 反向 WebSocket、HTTP Server 和 Token 配置。
5. 在 SnowLuma 中启用反向 WebSocket 客户端和 HTTP Server，两者使用显示的同一 Token；按回车启动 Bot。
6. 保持 Bot 窗口打开；需要停止时在窗口中按 Ctrl+C。

以后再次双击即可启动，已有配置不会被覆盖。


二、启用聊天采集（四槽或十七槽）
----------------------------

首次配置建议先启动采集，再启动 Bot：

1. 默认双击「启动聊天采集.cmd」使用原四槽。首次需要十七槽时，在项目目录的 PowerShell 运行：

       .\启动聊天采集.cmd -CollectorMode 17

   之后启动器会记住当前模式；菜单 5 可以在正常停止后切换 4/17 槽。
2. 四槽按提示填写 A、B、C、D 四个 Warframe 游戏昵称；十七槽填写 A～Q 十七个昵称。
   当前模式内每个槽必须使用互不重复的昵称，且与游戏内完全一致。十七槽的每个槽固定订阅一个
   地区的 G/Q/R/T 四频道，并且不在启动时查询频道成员。
3. 准备当前游戏版本已验证的 psk_current.bin。
   启动器会打开正确目录，复制文件后按回车继续。
4. 验证通过后会打开独立的「聊天采集监督器」窗口；该窗口必须保持运行。
5. 退出所有正在运行的 Warframe，在主向导选择「1. 全自动为尚未运行的槽登录取票」。
6. 首次使用时，按提示为待取票槽输入登录邮箱/账号和密码：
   - 密码输入时不会回显；凭据按 4/17 槽模式分别使用 Windows DPAPI 加密，只能由当前
     Windows 用户解密；
   - 脚本会按槽依次打开 Warframe 启动器、等待并点击「开始游戏」、填写凭据、等待聊天连接并只读
     扫描游戏内存；
   - 认证成功后该次使用的游戏会自动关闭，再处理下一个槽；
   - 不额外使用游戏账号 ID 校验槽位；槽位认证失败时会关闭该次游戏并继续其他槽。
7. 四槽 A～D 或十七槽 A～Q 都显示运行中后，输入 0 关闭主向导；监督器会继续运行。
8. 双击「启动BOT.cmd」。如果 Bot 原本已运行，需要重启以加载采集配置。


三、查看或停止采集
----------------

再次双击「启动聊天采集.cmd」可查看状态：

- 选择 1：全自动为尚未运行的槽登录并重新取票；
- 选择 2：刷新状态；
- 选择 3：打开当前模式的昵称配置文件；
- 选择 4：正常停止全部采集；
- 选择 5：正常停止后切换 4/17 槽模式；
- 选择 6：为指定的运行中槽手动执行一次成员快照；
- 选择 7：使用原有手动流程为尚未运行的槽逐个取票；
- 选择 8：配置或更新当前模式各槽的全自动登录凭据；
- 选择 0：只关闭向导，采集继续运行。

监督器每 30 秒显示槽位和频道状态。只有包含完整 OMG 紫卡链接的频道消息会保存；普通聊天和
普通物品链接会直接过滤。无法解码的坏链接不会推送，但同一消息中的其他有效卡仍会处理。
四槽会在启动时执行一轮限速 Delayed-WHOX 成员查询；十七槽只使用实时 JOIN、PART、QUIT、NICK，
默认不会补入采集启动前已经留在频道、之后又一直没有新事件的成员。两种模式都可从启动器菜单 6
选择运行中的槽，对该槽分配的全部频道执行一次成员快照；也可在项目目录的 PowerShell 中按需执行：

    uv run python scripts/run_chat_collector.py snapshot --slot B
    uv run python scripts/run_chat_collector.py snapshot-status

连接意外中断时，槽位会显示「正在自动重连」。worker 会在六小时有效期和十二次连续尝试上限内
复用仅保留在内存中的认证材料；明确拒绝、超过闸门或 worker 进程退出后才需要重新取票。断线期间
的频道消息不会回放。首次连接遇到临时网络失败也会自动重试，不会立即把候选判为无效。若手动成员
快照执行期间 worker 异常退出，下一次发起快照时会自动取消旧请求。

不要使用任务管理器单独结束某个 worker。正常停止后，应看到监督器、全部 worker 以及 Bot 中
尚未发送的当前代次 IRC 消息均已停止或撤销；已经进入发送 API 的消息仍可能完成发送。


四、常见问题
------------

1. 找不到 uv
   启动器会询问是否通过 Windows 软件安装器安装。没有 winget 时，请先在 Microsoft Store
   更新「应用安装程序」。

2. Bot 提示端口被占用
   通常是旧 Bot 仍在运行。关闭旧窗口后重新启动；如需修改端口，也要同步修改协议端地址。

3. 找不到 Warframe 或连接认证未完成
   全自动流程会自动识别官网独立版或 Steam 版；同时安装两种版本时默认使用官网独立版。开始前必须
   退出已有 Warframe 和 Warframe 启动器；脚本只接管并关闭自己启动的进程。确认 psk_current.bin
   对应当前客户端，且当前 Windows 用户已经完成设备验证。若提示无法只读打开进程，用与游戏相同的
   Windows 用户和权限级别重试。游戏提示账号或密码错误时，从菜单 8 更新当前模式的自动登录凭据。
   失败不会影响其他已成功槽，可返回菜单重试。

4. 全自动登录一直等待或窗口不受支持
   游戏登录不再按窗口坐标点击：脚本临时让游戏内部 UI 选择本槽账号，只向默认密码框发送密码和
   Enter。仍建议使用 16:9 或 16:10 的窗口化或窗口化铺满；就绪检测要求游戏客户区至少为
   480x270，宽高比在 0.90～3.50 之间，启动器客户区至少为 700x400。运行时不要最小化、遮挡游戏
   或持续抢占焦点；条件不满足时脚本会继续等待，不会盲目发送密码。临时修改的 EE.cfg 会在成功、
   失败或下次启动时还原。

5. 采集运行但 Bot 没有收到频道消息
   重启 Bot，使采集入口写入的 .env 配置生效；再确认目标已在管理控制台开启频道权限，并且
   至少有一条能命中该卡的狙击配置。

6. 需要提交运行记录排查
   采集日志位于 .runtime\chat_collector\logs，Bot 日志位于 .runtime\logs\bot.log。
